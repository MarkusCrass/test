# Перенос игры на Beget

Архив `myths-beget.zip` содержит готовый клиентский 3D-бандл, поэтому собирать Three.js на хостинге не требуется. Нужен Node.js 18+ и поддержка Node-приложений через Apache Passenger.

## 1. Подключить SSH и Node.js

1. В панели Beget включите SSH для аккаунта.
2. Подключитесь по SSH. Для этого технического домена обычно используется:

   ```bash
   ssh ezekie6n@ezekie6n.beget.tech
   ```

3. Перейдите в Docker-окружение Beget:

   ```bash
   ssh localhost -p 222
   ```

4. Проверьте версию:

   ```bash
   node -v
   npm -v
   ```

Если Node.js отсутствует или версия ниже 18, установите его по официальной инструкции: https://beget.com/ru/kb/how-to/web-apps/node-js. На некоторых серверах также необходимо открыть общий доступ к `~/.local`, как описано в той же инструкции.

Пароль и другие секреты хостинга не нужно отправлять в чат.

## 2. Загрузить игру

1. Откройте файловый менеджер Beget.
2. Перейдите в каталог сайта `~/ezekie6n.beget.tech/`.
3. Загрузите туда `myths-beget.zip` и распакуйте его.
4. Должен появиться каталог `~/ezekie6n.beget.tech/myths/` с файлами `server.js`, `package.json`, `public/` и остальными.

## 3. Запустить установку

В Docker-терминале выполните:

```bash
cd ~/ezekie6n.beget.tech/myths
bash deploy/beget/setup.sh
```

Скрипт:

- проверит Node.js 18+ и наличие готового 3D-бандла;
- выполнит `npm ci --omit=dev`;
- создаст `.htaccess` с правильными абсолютными путями Passenger;
- переименует прежний `public_html` в резервную копию, ничего не удаляя;
- создаст ссылку `public_html -> myths/public`;
- создаст `tmp/restart.txt` для запуска/перезапуска Passenger.

## 4. Проверить

1. Откройте `http://ezekie6n.beget.tech/health` — должен вернуться JSON с `"ok":true`.
2. Откройте `http://ezekie6n.beget.tech/` и начните одиночную тренировку.
3. Откройте сайт во втором браузере и проверьте создание/подключение к комнате. Это одновременно проверит WebSocket `/ws`.

Если Beget не пропускает WebSocket, клиент автоматически переключается на резервный HTTP long-poll канал через `/api/`. Для принудительной проверки резервного режима откройте сайт с параметром `?transport=http`. Обычные WebSocket-подключения продолжают поддерживаться и используются в первую очередь.

Если страница и `/health` работают, но не подключаются оба транспорта, проверьте, что запросы `/api/connect` и `/api/poll` доходят до Passenger и не блокируются настройками тарифа.

После успешной проверки включите бесплатный SSL-сертификат в панели Beget. Клиент автоматически перейдёт с `ws://` на защищённый `wss://` вместе со страницей.

## Обновление и откат

Для перезапуска после обновления файлов:

```bash
cd ~/ezekie6n.beget.tech/myths
touch tmp/restart.txt
```

Чтобы вернуть прежний сайт, удалите только новую символьную ссылку `public_html`, переименуйте обратно резервный `public_html.backup-ДАТА-ВРЕМЯ` и восстановите прежний `.htaccess`, если он был.
